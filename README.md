# Networking Portfolio

Hands-on networking labs I've built while working toward a career in network engineering. Each folder contains the lab file (or saved device configs for emulator labs), a topology screenshot, and a short write-up explaining what it is and what I learned building it.

**Currently working toward:** Cisco CCNA, with a focus on hands-on labs and network automation.

## Labs

- **[Configuring Default Routing](default-route-isp-uplink/)** — Addressed an ISP-facing /30 on a site router and installed a default route on Cisco IOS-XE (CML), so a LAN host could reach an external test address. Verified with a ping to the ISP next hop, `Gateway of last resort` and `S*` in the routing table, and a 5-of-5 ping from a Linux PC on the LAN. Includes notes on longest-prefix match against an existing static route and why the lab works without NAT.
- **[Configuring Static Routing](static-routing-two-sites/)** — Added one static route on each of two site routers on Cisco IOS-XE (CML) so their LANs could reach each other across a /30 link. Verified with `show ip route static` on both routers, a router-to-server ping, and a host-to-host ping from a Linux server across both routers. Includes notes on why the router's own ping does not prove the return route, and reading the hop count from the reply TTL.
- **[Configuring Local Routing](connected-routes-two-routers/)** — Joined two site routers with a /30 point-to-point link on Cisco IOS-XE (CML), addressed each LAN, and confirmed the connected routes on both sides with `show ip route connected` and pings across the link. Includes a troubleshooting write-up on addresses applied to the wrong interfaces, the `overlaps with` error that blocked the fix, and a /24 vs /30 mask mismatch that a ping did not catch.
- **[Two-Router Interface Activation](two-router-p2p-link-activation/)** — Audited two staged routers against a security standard (type 9 secrets, local login, login logging), brought up a LAN gateway on each, and linked them over a `10.8.0.0/30` point-to-point on Cisco IOS-XE (CML). Verified with connected routes, pings in both directions, clean interface counters and the saved startup config. Includes notes on three commands IOS accepted silently that did the wrong thing: a user named "secret", an unused plaintext console password, and `vty` expanding to `vty-async`.
- **[Linux Lab Setup](linux-lab-setup/)** — Packet Tracer lab file. Write-up in progress.
- **[Configuring Router Interfaces](router-interfaces-and-baseline/)** — Gave a branch router a login baseline (local username on console and VTY, enable secret), brought its LAN interface up with an address and description, and labelled a shut WAN port for a future carrier circuit on Cisco IOS-XE (CML). Verified with `show interfaces description`, `show cdp neighbors`, a ping to the switch and the saved startup config. Includes notes on why `ex` is ambiguous in some modes and what happens when two commands are pasted on one line.
- **[Configuring Switch Interfaces](switch-duplex-and-management-ip/)** — Labelled the live ports on two access switches, confirmed full duplex with zero collisions, then built a management VLAN 42 with SVIs and an 802.1Q trunk on Cisco IOS-XE (CML). Verified with `show interface status`, interface counters, `show interface trunk` and pings between the SVIs. Includes a troubleshooting write-up on an SVI stuck down/down because its VLAN was never created, and a ping that failed on an access/trunk mismatch.
- **[Tracking Devices with the CAM Table](cam-table-device-tracing/)** — Took two IP-only tickets (a slow user and a server flagged by security) and found each device's exact switch port using only switch access: `ping` + `show arp` to turn the IP into a MAC, then `show mac address-table` hop by hop across a core-to-access uplink. Mapped the topology from CAM tables with no diagram provided. Includes notes on host vs IOS ARP commands and why a MAC showing up on an uplink isn't the device's real location.
- **[Exploring Switch CAM Tables](switch-cam-table-learning/)** — Generated ARP and ICMP traffic between two Linux hosts and watched an IOS-XE switch (CML) learn their MACs on the right ports, cross-checking each CAM entry against the host's `ifconfig`. Then flushed the dynamic entries with `clear mac address-table dynamic` and let live traffic rebuild them. Includes notes on instant re-learning and why the switch CAM table and the host ARP cache are separate.
- **[Switch Interfaces and the CAM Table](switch-interfaces-cam-table/)** — Read-only audit of an aggregation switch on Cisco IOS-XE (CML): port roles from descriptions, duplex/speed and error-counter health checks, and MAC address table lookups to find each device's port and spot the trunk uplink to the core. Verified against every completion check with captured show output. Includes a troubleshooting note on NX-OS vs IOS command syntax.
- **[District Shop Bring-Up](district-shop-bring-up/)** — Took two access switches and an edge router from factory state to a hardened, manageable baseline on Cisco IOS-XE (CML): hostnames, MOTD banner, enable secret, encrypted console/VTY passwords with SSH-only VTY, port descriptions, management SVIs and default gateway. Verified with saved configs, a reload test, and pings to the gateway. Includes a troubleshooting write-up on catching a pasted `copy` command that never saved the config.
- **[Wireless Router and Client](wireless-router-and-client/)** — Built and secured a SOHO home network in Cisco Packet Tracer: cable-modem internet, DHCP addressing, a WPA2-secured wireless LAN, and both wired and wireless clients reaching the internet. Graded 100%. Includes a troubleshooting write-up on diagnosing and recovering from an admin-credential lockout.
- **[Connected Devices](connecting-devices/)** — Connecting and configuring end devices in Cisco Packet Tracer and verifying end-to-end connectivity across the topology.
- **[Intro to Packet Tracer](intro-to-packet-tracer/)** — First lab: learning the Packet Tracer environment and building a basic working topology from the ground up.
